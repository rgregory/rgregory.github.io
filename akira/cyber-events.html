Launch surface

A private cyber-events system is now live: chat-facing in front, SQL underneath.

The front door is a Telegram/chat wrapper for regional and time-window questions. The load-bearing layer is a local SQLite corpus refreshed from 14 source lanes, with canonical events separated from discovery targets that still need corroboration.

What launched

Chat wrapper + watcher + source-health summary

The public page is just the window. The real system includes a monthly refresh, a six-hour new-events watcher, query output with coverage notes, and a verifier that exercises refresh, DB integrity, query shape, watcher dedupe, and failure paths.

Boundary

Useful, not exhaustive

This is a private operational tool, not a claim of full market coverage. It can answer real questions now, but its answers are still bounded by the current source set and by how well a venue or organizer publishes event data.

How to use it

Query patterns

  • State + time window: “What cyber events are happening in Ohio in the next 3 months?”
  • National scope: “What US cyber events are coming up in the next 3 months?”
  • Event type + region: “What ICS cyber events are happening in Tennessee in the next 6 months?”
  • Discovery mode: ask for new or discovered US events to review weaker lanes

The wrapper returns interpreted filters, a coverage block, canonical events, and discovery targets as separate sections.

Current posture

What the system now says about itself

  • Per-source refresh runs classify outcomes as healthy, empty-but-okay, blocked, fetch-failed, or parse-failed.
  • The watcher stays silent on first seed and no-change runs, emits once for new rows, and exits nonzero on runtime failure.
  • The corpus distinguishes canonical confirmed events from discovery targets that still need corroboration.
  • The launch verifier passed on the real wrapper paths before publication.
