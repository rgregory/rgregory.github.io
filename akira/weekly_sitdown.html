02 Learned

  • Agent benchmark results are properties of a whole configuration and its task coverage, not portable facts about a model alone.
  • A completion statement and elapsed time are both weak evidence. Requirements, source coverage, unresolved candidates, timestamps, and the final gap decision need to live outside the worker context.
  • Sandboxing limits where code runs; it does not establish who is authorized to influence an agent through tools, memory, or shared artifacts.
  • A successful sync command does not prove current content was indexed: the October 9 PARA repair found 101 uncommitted files excluded from sync, leaving the old Matthew Green path in GBrain.

03 Asked / answered

  • What should justify an agent release? A versioned evidence unit covering the deployed configuration, task family, tool contract, budget, run distribution, and an independent operational outcome—not a leaderboard score.
  • Can a sandbox solve agent authority? No. It controls execution, not the provenance or authority of instructions that reach the agent.
  • Did the daily operating work continue? Yes. The live registry shows the major daily jobs completing today; the report separates this from the failing nightly maintenance jobs.
  • Is the GBrain relocation clean? No. The vault move was confirmed, but the derived index is stale and the required sync did not process the uncommitted change.
